# Introduction

![Status: Planned](https://img.shields.io/badge/status-Planned-blue)

This plan implements GitHub issue [#291](https://github.com/shaes-farm/time-traveler/issues/291) — the server-side query layer the cross-entity **Media Library** (screen 17 / Batch I) sits on. It is the first work item of epic [#297](https://github.com/shaes-farm/time-traveler/issues/297) and the backend foundation the `MediaPicker` primitive (#292) and the library route (#294) consume.

Scope is confined to `packages/services`: a faceted, paginated, searchable library-list query over all `media` the current user can see (search across `alt_text`/`caption`/filename-`slug`; Type/Source/Attached-to facets with per-option counts; cursor pagination over `created_at`/`slug`), a cross-entity **attachment map** that resolves where each `media` row is used across `event_media`/`character_media`/`timeline_media`, **orphan detection** (zero junction rows), Zod schemas/types, and Vitest unit coverage. No new SQL migration is required — the `source` discriminator (migration `00018`) and `is_primary` (migration `00013`) already exist on `main`.

## 1. Requirements & Constraints

- **REQ-001**: Add a library-list query in `packages/services/src/modules/media-service.ts` that filters all `media` the caller can see, supporting search + facets + pagination in a single round-trip plus facet-count round-trips.
- **REQ-002**: Search must be a case-insensitive substring match spanning `alt_text`, `caption`, and the filename/`slug` (PostgREST `.or(...ilike...)`). Full-text over `metadata` is explicitly out of scope.
- **REQ-003**: Facets — **Type** (`media_type` closed set: `image|video|audio|document`), **Source** (`upload|external`), **Attached to** (`events|characters|timelines|orphaned`). Combine **AND across groups, OR within a group**, matching the events-list filter-rail behavior.
- **REQ-004**: Source facet must use the real `source` discriminator column (migration `00018`), NOT the `storage_path IS NULL` stopgap.
- **REQ-005**: Return per-option **facet counts** for the filter rail (count for each Type value, each Source value, each Attached-to bucket including `orphaned`).
- **REQ-006**: **Cursor pagination** over `created_at` (with `slug`/`id` as the deterministic tiebreaker), forward direction; return an opaque next-cursor and `hasMore`. No infinite scroll, no offset/`total` requirement (explicit pager UI is the consumer; total is derivable from `count: "exact"` if cheap).
- **REQ-007**: **Attachment map** — for a single `media` id AND in bulk for a page of ids, resolve attached entities as `{ kind: 'event'|'character'|'timeline', id, label, is_primary? }[]` across the three junctions. `label` is `events.title`, `characters.name`, `timelines.title`. `is_primary` is populated ONLY for `character_media` (read-only here).
- **REQ-008**: **Orphan detection** — a `media` row with zero rows across all three junctions is an orphan (`⛓ 0`). Orphaned must be selectable as a first-class Attached-to filter value and counted in facet counts.
- **SEC-001**: All queries must respect RLS/collaborator visibility. The service issues queries through the passed `SupabaseClient<Database>` and adds NO `service_role` escalation. Orphan visibility follows the `media` row's own ownership (the `media` RLS policy), not any entity's.
- **SEC-002**: Any value interpolated into a PostgREST filter string (`.or(...)`) must be sanitized/whitelisted before interpolation — search terms must escape PostgREST reserved characters (`,`, `(`, `)`, `*`, `:`), and facet enum values must be validated against the canonical Zod enums before use, mirroring the era-filter precedent in `event-service.ts:293-303`.
- **CON-001**: No new SQL migration. `media.source` (`00018`) and `character_media.is_primary` (`00013`) already exist. If a count cannot be computed without a DB function/view, prefer multiple PostgREST round-trips over adding a migration in this issue; flag any genuine need for a DB function as a follow-up issue per the CLAUDE.md upstream-bug process.
- **CON-002**: Strict TypeScript — `strict`, `strictNullChecks`, `noUncheckedIndexedAccess` all on. No `any`; existing module casts via `as unknown as <T>` only where PostgREST embed typing forces it (see `event-service.ts:347`).
- **CON-003**: Zero-warnings lint (`eslint --max-warnings 0`); ESM only.
- **GUD-001**: Mirror the existing `getEventsPage` faceted-list conventions in `event-service.ts:211-350` — `count: "exact"`, aggregate `(count)` embeds, `!inner(count)` for has-at-least-one, plain column embed + `.is(..., null)` for has-none, `.or()` for OR-within-group.
- **GUD-002**: Keep the existing `getMedia`/`MediaFilters` API intact (it is consumed by the #49 per-entity core). Add the new library query as additional exports; do not break the current signature.
- **PAT-001**: Follow the module's `assertNoError(error, context)` error-wrapping pattern (`media-service.ts:58-65`) for every query.
- **PAT-002**: Tests use the in-file `makeBuilder`/chainable-mock pattern from `media-service.test.ts:18-33`; extend it with `.or`, `.ilike`, `.in`, `.lt`/`.gt`, `.limit`, and `count` support as needed.

## 3. Alternatives

- **ALT-001**: Offset/`range` pagination (as `getMedia` uses today). Rejected — the issue mandates cursor pagination over `created_at`/`slug` for large libraries; offset pagination drifts under concurrent inserts and is slow at depth.
- **ALT-002**: A dedicated SQL view or RPC (e.g. `media_with_attachment_counts`) computing counts and orphans server-side in one round-trip. Rejected for this issue to honor CON-001 (no new migration); if PostgREST embed counts prove insufficient/slow, file a follow-up to add a view/function. Noted as the natural optimization for a later pass.
- **ALT-003**: Client-side facet counting from a full fetch. Rejected — does not scale (248+ items, paginated) and the issue requires server-side facet counts.
- **ALT-004**: A single mega-query returning rows + all facet counts + attachment map. Rejected — PostgREST cannot express conditional per-group faceted counts in one statement cleanly; separate, well-typed functions are more testable and match the existing `getEventsPage` split.

## 7. Risks & Assumptions

- **RISK-001**: PostgREST may not express conditional per-group faceted counts in a single round-trip; mitigation — per-option head-count queries (`{count:"exact", head:true}`), documented, with a follow-up issue if N round-trips prove too slow (ALT-002).
- **RISK-002**: Keyset cursor `.or("created_at.lt.X,and(created_at.eq.X,slug.lt.Y)")` syntax must be verified against the live PostgREST stack (the events service has analogous "verified against the live stack" comments). Mitigation — verify with `pnpm run db:start` + a manual query before finalizing; capture the exact working filter string in a code comment.
- **RISK-003**: The Attached-to OR-within-group across three different junctions is the trickiest PostgREST construction. Mitigation — if a single query is not expressible, fall back to resolving candidate media ids via bulk attachment lookup and filtering ids, documented inline.
- **RISK-004**: Orphan visibility correctness depends on `media` RLS, not junction RLS; an orphan has no junction rows so its visibility is solely the `media` row's. Tests use the passed client; true RLS behavior is covered by existing pgTAP — no new pgTAP required for this issue unless a gap is found.
- **ASSUMPTION-001**: **(Resolved)** #49 merged to `main` via PR [#287](https://github.com/shaes-farm/time-traveler/pull/287) (2026-06-22); branch #291 directly from `main`. No rebase-onto-#49 coordination required.
- **ASSUMPTION-002**: No new migration is needed; `source` and `is_primary` columns and all junction grants/policies already exist on `main` (verified: migrations `00013`, `00018`, `00023`).
- **ASSUMPTION-003**: Consumers (#292 `MediaPicker`, #294 route) want a pull-based pager (`nextCursor`/`hasMore`), not a total-pages count; `total` via `count:"exact"` is provided opportunistically but not load-bearing.
